# CLAUDE.md

Памятка для ИИ-ассистента (и человека), который продолжает работу в этом репозитории с нуля.

## Что это

Независимая открытая DAW для macOS со своими синтезаторами (Prisma, позже Alloy): сессия с запуском клипов по сетке дорожек и сцен, линейная аранжировка с дублями и punch, запись MIDI и звука, свои эффекты и микшер. C++20 + JUCE 8, лицензия AGPLv3. Владелец проекта Silver-Season.

Языки: с владельцем общаемся по-русски; тексты интерфейса пока русские (все в `app/Source/Strings.h`, английский перевод с переключателем языка будет отдельным этапом); код, комментарии, сообщения коммитов и документация для внешнего читателя (README.md, docs/ARCHITECTURE.md, docs/spec/README.md) на английском. Русская версия README лежит в README.ru.md, её обновляем вместе с README.md. Программу описываем по тому, что она делает, без сравнений с другими DAW.

## Как собрать и проверить в Linux-контейнере

```bash
sudo apt-get update && sudo apt-get install -y libasound2-dev libxrandr-dev libxinerama-dev libxcursor-dev \
     libfontconfig1-dev libgl1-mesa-dev libxcomposite-dev xvfb xdotool imagemagick
cmake -S . -B ../build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build ../build && ctest --test-dir ../build --output-on-failure
```

Скриншоты интерфейса: `Xvfb :99 -screen 0 1600x1000x24 &`, затем `HOME=<пустая папка> DAW_NULL_AUDIO=1 DAW_THEME=prism|neon|studio|paper ../build/app/DAW_artefacts/Release/DAW`. Окно называется по имени проекта («Без названия»), растягивается через `xdotool windowsize`, снимок через `import -window root`. На Mac собирает `./scripts/build-mac.sh`, CI собирает macOS и Linux и публикует nightly DMG из `main`.

## Грабли, на которые уже наступали

- **Клавиши читаются по коду, а не по символу.** У владельца русская раскладка: `getTextCharacter()` отдаёт кириллицу, а `getKeyCode()` остаётся латинским. Любая новая горячая клавиша сравнивается по коду (см. `keyLetter` в `plugins/prisma/Source/PrismaEditor.cpp` и `app/Source/ui/ComputerKeys.cpp`).
- **Тесты движка без настоящего аудиоустройства:** `AudioEngine` в тестах создаётся с `openDevices = false`. На macOS CI настоящий CoreAudio-колбэк гонялся с ручным и ронял тесты.
- **Цвета только из темы.** Весь интерфейс берёт цвета через `theme()` (JSON-токены в `app/Resources/themes`), поэтому новый экран сам выглядит правильно во всех четырёх темах. Своих цветов в коде не заводить. Исключение пока одно: окно Prisma, его переведём на темы на этапе синтов.
- **Все строки интерфейса в `app/Source/Strings.h`.** Так позже добавится английский перевод отдельным небольшим этапом.
- **Аудиопоток:** никаких выделений памяти, блокировок, `juce::String`, `ValueTree`. В Debug есть `DAW_RT_CHECKS`, тест «no heap use» должен оставаться зелёным.
- **Одно действие = одна транзакция отмены**, жест мышью тоже одна транзакция.

## Как принято работать

- Ветка на этап, PR в `main`, merge только при зелёном CI. Описание PR: «Before / After / How».
- В каждом этапе тесты на каждую задачу и скриншоты нового интерфейса во всех четырёх темах (`media/`), README.md (по-английски) и README.ru.md дополняются разделом этапа.
- Владелец проверяет вживую на Mac (звук, внешняя карта, MIDI-клавиатура) после каждого этапа и присылает замечания одним сообщением. Ставит DMG, когда ему сказали «можно ставить», а не после каждого merge.
- Codex используется только для изолированных задач (иконки, иллюстрации), не для движка и интерфейса.
